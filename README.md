# Прогноз недельных продаж на 9 недель

ML-модель и автономный FastAPI-сервис прогнозируют сумму `quantity` за неделю для пары `warehouse_name × article`. В репозитории находятся готовые веса; для запуска API переобучение не требуется.

[Сборка, запуск и API](forecast-container/README.md) · [Техническое задание](docs/requirements/ТЗ_хакатон_обновлен.md) · [FAQ организаторов](docs/requirements/FAQ_Первый_чекпоинт.md) · [Итоги проверки](docs/reports/IMPLEMENTATION_WEEKLY_RU.md) · [Все сохранённые эксперименты](experiments/README.md)

## Быстрый запуск

Требуется Docker Engine с Linux-контейнерами; проверенная версия — 29.7.2. GPU не нужен. Команды выполняются из корня клонированного репозитория:

```bash
docker build -t forecast-api-weekly ./forecast-container
docker run --rm -p 127.0.0.1:8000:8000 forecast-api-weekly
```

Swagger: http://localhost:8000/docs. Проверка готовности: http://localhost:8000/health, поле `model_loaded` должно быть `true`.

```bash
curl -f -X POST http://localhost:8000/predict \
  -F "sales=@forecast-container/data/sample_sales_6mo.csv" \
  -F "stock=@forecast-container/data/sample_stock_6mo.csv" \
  -o forecast.csv
curl -f "http://localhost:8000/predict?article=char_article_0" -o article.csv
curl -f "http://localhost:8000/predict?warehouse=warehouse_name_0" -o warehouse.csv
curl -f "http://localhost:8000/predict/all?format=json" -o forecast.json
```

POST принимает два CSV и рассчитывает прогноз. GET возвращает последний успешный результат, доступен фильтр по артикулу и/или складу. Выходные колонки: `week,warehouse_name,article,quantity`. Параметры, ошибки и полный набор примеров описаны в [README контейнера](forecast-container/README.md).

## Даты и данные

| Сценарий | Допустимая история | Первая неделя | Горизонт |
|---|---|---|---|
| Основное соревнование | sales и stock по 26.07.2026 включительно | 27.07.2026 | 9 полных недель, последний день 27.09 |
| API | загруженные CSV, минимум 180 календарных дней | следующий календарный понедельник после max(sales.date) | 9 полных недель |

Quantity суммируется по неделе через департаменты/города. Дневные дубли stock суммируются, отрицательные остатки сохраняются. Денежные поля не используются в рабочей модели; собственный log1p недельного target применяется внутри одной ветви ансамбля и обращается через expm1.

Полные исходные CSV организаторов нужно отдельно поместить в локальный `data/`. Они не входят в Git и Docker-образ. Папка `forecast-container/data/` содержит только примеры: первые 100 строк и небольшой срез с достаточной для API глубиной истории.

## Модель и качество

Direct weekly ансамбль: 0,3 × hurdle LightGBM + 0,7 × LightGBM на log1p недельного количества, 37 признаков. Округление выбрано на первом историческом окне и проверено на втором. Веса, препроцессор и параметры находятся в `forecast-container/model/`; даты обучения и отбора ограничены 26.07.2026.

Независимое подтверждение за 25.05–26.07.2026:

| Метрика | Модель | Бейзлайн «последняя неделя» |
|---|---:|---:|
| SMAPE, % | 59,8408 | 74,4871 |
| WAPE, % | 46,8954 | 58,4241 |
| RMSE | 3,3251 | 3,9754 |
| Средний абсолютный Bias по сериям, % | 72,8448 | 120,6991 |
| RMSLE | 0,5066 | 0,6178 |

Это историческая оценка, не официальный ранг и не измеренная точность конечного submission. Занижение общего объёма составляет 18,83%; оно отличается от среднего абсолютного Bias по сериям. Дневные 28–30% SMAPE с недельными 59,84% напрямую не сравниваются: меняются точки оценки, доля нулей и временные окна. [Причины и гипотезы](docs/reports/METRICS_COMPARISON_RU.md).

Сохранённые проверки от 27.10.2026: 102 теста; Docker-инференс без сети при лимите 7 GiB/8 CPU, POST 36,26/34,98 с, GET CSV 0,130 с, JSON 0,077 с; образ 305,5 MB. Повторные POST одинаковы, значения совпали с submission. Точный пик памяти контейнера не измерялся. [Журналы проверок](forecast-container/logs/README.md).

## Воспроизведение и submission

Для локального Python-запуска проверены Python 3.10/3.11; Docker использует 3.11. Зависимости зафиксированы в requirements.lock.txt, тестовые — в requirements-dev.txt.

```bash
cd forecast-container
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
python generate_submission.py --allow-observed-pairs
```

Последняя команда требует отдельно предоставленных исходных CSV и создаёт локальный `submission/weekly_observed/forecast.csv`. Он предварительный по покрытию: официальный каталог пар отсутствует. Для 8 777 наблюдаемых пар получается 78 993 строки. Условные 79 101 строка из ТЗ относятся к полному произведению 11 × 799.

При получении эталонного списка следует использовать `--required-pairs path.csv`; автоматического добавления неизвестных пар нет. Команды обучения, скоринга, проверки и упаковки — в [инструкции контейнера](forecast-container/README.md). Существующие результаты не перезаписываются без явно поддерживаемого флага или нового выходного пути.

## Известные ограничения

- Соответствие состава пар скрытому эталону не подтверждено.
- Российские праздники и переносы выходных явно не учтены; есть month/week_of_year/year.
- Недельная модель исследована ограниченно; текущие окна уже просмотрены и не подходят для нового независимого подтверждения после повторного подбора.
- API хранит один последний прогноз на процесс. Очереди, пользовательской истории и отдельного веб-интерфейса нет.
- Качество на новых данных и время на другом оборудовании не гарантируются приведёнными измерениями.

[Полный повторный аудит и направления улучшения](docs/reports/RECHECK_TZ_AND_IMPROVEMENTS_RU.md). Основная сдача — CSV и код; Docker/API является дополнительным заданием. Публикация репозитория сама по себе не заменяет передачу финального submission и уведомление организаторов.
