# Прогноз продаж на 64 дня

MVP для прогнозирования ежедневных продаж по паре «склад × товар»: ансамбль LightGBM, HTTP API и автономный Docker-контейнер. GPU не требуется.

## Быстрый запуск

```bash
cd forecast-container
docker build -t forecast-api .
docker run --rm -p 127.0.0.1:8000:8000 forecast-api
```

Проверка: `http://localhost:8000/health`, описание API: `http://localhost:8000/docs`.

```bash
curl -f -X POST http://localhost:8000/predict -F "sales=@data/sample_sales_6mo.csv" -F "stock=@data/sample_stock_6mo.csv" -o forecast.csv
```

Подробнее: [сборка, API, тесты и ограничения](forecast-container/README.md).

## Структура для сдачи

Основной каталог соответствует п. 10.5 ТЗ. Дополнительные файлы нужны для воспроизводимости и проверки качества.

```text
forecast-64-v1/
├── README.md
└── forecast-container/
    ├── Dockerfile
    ├── docker-compose.yml
    ├── requirements.txt
    ├── requirements.lock.txt   # фиксированные runtime-зависимости
    ├── requirements-dev.txt    # зависимости тестирования и оценки
    ├── README.md
    ├── app/                    # API, признаки, модели, валидация
    ├── model/                  # финальная модель, preprocessor, config
    ├── data/                   # 100 строк для формата + рабочие 6mo-примеры
    ├── tests/                  # HTTP-самопроверка и регрессионные тесты
    ├── scripts/                # примеры и независимая проверка модели
    ├── logs/                   # только пояснение и verified_summary.json
    ├── train.py                # воспроизведение обучения
    ├── evaluate.py             # оценка с проверкой временной границы
    ├── baseline.py             # сравнение с простыми прогнозами
    └── generate_submission.py  # CSV и проверки контракта сдачи
```

Финальная модель и примеры данных включены в Git: после клонирования контейнер собирается без доступа к исходной обучающей выборке. Все модули `app/models/` сохранены: они входят в реестр моделей и используются кодом обучения/загрузки.

## Что остаётся локально

Корневые `data/` с исходными CSV и ТЗ, `docs/` с рабочими материалами, `artifacts/` с восстановлением и OOF, `submission/` с финальным CSV и архивом, старое `demo/`, локальный аудит, служебные настройки, старые лаборатории и промежуточные модели исключены через `.gitignore`. Файлы не удаляются с диска. Финальный CSV передаётся отдельно от Git.

Изменение `.gitignore` не удаляет файлы из прошлых коммитов. История репозитория сохраняется; старые эксперименты доступны в ней.

## Проверенный статус

22.10.2026 образ успешно собран и проверен через HTTP в изолированной сети Docker без доступа в интернет. Два полных POST: 47,4 и 46,6 секунды; результаты побайтно одинаковы и по значениям совпадают с подготовленным submission. Пик памяти сервиса — 5,84 ГиБ; GET полного CSV — 0,79 секунды, JSON — 0,47 секунды. Условия: Docker Desktop, Linux-контейнер, лимит 7 ГиБ RAM и 8 CPU. Это измерения конкретного запуска, не гарантия для любого оборудования. Дополнительно прошли 27 регрессионных тестов.

Уточнения судей имеют приоритет: cost_price/volume_weight не обязательны, отрицательный stock принимается, верные нули включаются в среднее SMAPE. Прогноз содержит наблюдаемые пары sales: на полном train 8 777 × 64 = 561 728 строк. Число 562 496 из ТЗ соответствует декартову произведению; точный справочник приёмки сверх наблюдаемых пар пока не согласован.

## Воспроизведение

```bash
cd forecast-container
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
# Полные данные организаторов нужно отдельно положить в корневой data/:
python generate_submission.py
```

Генератор создаёт `submission/forecast.csv` и manifest; существующий CSV без `--overwrite` не перезаписывает. Веса финальной модели сохраняются в `forecast-container/model/`; локальная точка восстановления — `artifacts/recovery/original-20261022/`.
