# Расхождение результатов и воспроизводимость лучшего сабмита

Проверено 31.10.2026. Лучший из четырёх отправленных вариантов по скриншоту пользователя — **joint_candidate_forecast**, score **0,370968**. Он воспроизведён и установлен в локальные `model/` и `forecast.csv`. Новое исследовательское обучение не запускалось; использованы готовые веса из возвращённых архивов.

## Что установлено по ТЗ

Прочитаны исходные `ТЗ_хакатон_обновлен.md`, `FAQ_Первый_чекпоинт.md` и сводка `HACKATHON_RULES_AND_CONTEXT_RU.md`.

- Результат — сумма продаж за календарную неделю, девять полных недель, понедельники 27.07–21.09.2026; последний день — 27.09.2026.
- История и цели обучения — не позднее 26.07.2026. Будущие остатки также исключаются.
- SMAPE и абсолютный Bias усредняются по сериям; WAPE/RMSE/RMSLE считаются глобально. Нули не удаляются из SMAPE, серии с нулевым фактическим средним исключаются только из Bias.
- Веса — 50/20/15/10/5. Таблица использует ранги: `(rank−1)/31` для 32 сабмитов. Это не сумма сырых метрик и не взвешенное среднее отношений к нашей модели.
- Контейнер должен воспроизводить основной прогноз по качеству, работать автономно и детерминированно. Ограничение полного POST — 60 минут, RAM — 64 GB, размер образа — 30 GB.

## Почему локально v2 был лучше, а у судей хуже

| Метрика | Старый joint: среднее январь/март | Новый joint v2: среднее январь/март | Старый joint: судьи | Новый joint v2: судьи |
|---|---:|---:|---:|---:|
| SMAPE | 61,237520 | 61,134864 | 61,556648 | 61,557095 |
| WAPE | 47,982221 | 47,928508 | 49,142695 | 49,211246 |
| RMSE | 2,536397 | 2,534189 | 4,157557 | 4,154562 |
| Bias | 72,863502 | 72,540241 | 87,498300 | 87,672584 |
| RMSLE | 0,515061 | 0,514270 | 0,544662 | 0,544563 |

**Установленные причины несоответствия ожиданий:**

1. Мы использовали локальный суррогат: среднее взвешенных отношений ошибок к базовой модели. Он не равен официальному ранговому score. Называть его приростом официального score было бы неверно.
2. Январь и март многократно использовались для адаптивного выбора сотен вариантов. Преимущество нового joint над старым на них небольшое и не подтверждено независимым периодом. Переносимость этого преимущества была переоценена.
3. На скрытом периоде направления изменений действительно другие: SMAPE, WAPE и Bias ухудшились; RMSE и RMSLE улучшились. Это не только изменение состава таблицы.
4. Ранги усилили небольшие изменения. SMAPE ухудшился всего на 0,000447 п.п., но потерян один ранг. По WAPE потеряны три ранга. Итого новый score хуже на **0,032258**.

Вклад изменений в score: SMAPE +0,016129; WAPE +0,019355; RMSE −0,004839; Bias +0,003226; RMSLE −0,001613. Сумма воспроизводит разницу 0,403226 − 0,370968 с точностью округления скриншота.

Новый joint отличается от старого в 4 340 строках из 79 101; максимальное изменение — 3 единицы, общий прогноз выше на 1 068 единиц. Это иной файл, не переименование и не дубликат.

**Что проверено и не объясняет расхождение:** формулы локальных метрик совпали с функциями, извлечёнными из исходного ТЗ; сумма семи дней и привязка к неделе корректны; сохранённые предсказания и признаки воспроизведены точно. Дневные SMAPE около 29% относятся к другой гранулярности и не сопоставимы с недельными 61%.

Сезонность, изменение частоты нулей и крупных продаж — возможные причины изменения обобщения. Без скрытого факта судей нельзя доказать конкретную причину по сегментам или объяснить уровень внешнего RMSE только одним фактором. Скриншот содержит имена файлов и округлённые метрики, но не контрольные суммы на стороне судей.

## Точный граф лучшего сабмита

1. Сохранённая недельная основа и обновлённый недельный рецепт смешиваются с весами 75/25 для горизонтов 1–6 и 50/50 для 7–9. В первой ветви при прошлом спросе `0.5 <= mean_28*7 < 10` применяется уточнённый count-декодер: lambda 3 в начале и 6 в хвосте. Прочие сегменты сохраняют исходную основу. Округление недельной ветви — `floor(max(p,0)+1−0.65)`.
2. Дневной эксперт `weekly_poisson_aux`, 10 итераций, 66 признаков. Используется его исходный raw-score с сохранённым past-only offset и экспонентой. Семь дневных прогнозов суммируются; недельный event-gate равен 0,5; затем `np.rint`.
3. Итог — `np.rint(0.65*weekly + 0.35*daily_weekly)`.
4. Для 12 пар без совместной истории — прежний fallback; 108 соответствующих строк сохранены.

Новые count-модели из weekly refinement в этот граф не входят. Полная спецификация — `model/config.json`, `serving_profile=joint_v1`, preprocessing v9. API использует данные запроса, без чтения файлов `artifacts/` и исходных train CSV.

## Повторение

Из корня с доступными исходными sales/stock:

```powershell
python generate_submission.py --required-pairs required_pairs.csv --out forecast_reproduced.csv
python scripts/verify_release.py
docker build -t forecast-api .
docker run --rm --name forecast-api -p 127.0.0.1:8000:8000 forecast-api
```

На тех же исходных данных значения совпадают с лучшим CSV; Linux может изменить только перевод строк. `generate_submission.py` сам дважды рассчитывает прогноз и проверяет детерминизм. Для API входные файлы передаются через POST и должны содержать минимум 180 календарных дней истории; для сравнения с данным CSV они должны быть обрезаны по 26.07.2026.

Релиз публикуется единым коммитом: код, `model/`, `forecast.csv`, manifest и эти отчёты согласованы. Для проверки по GitHub следует использовать текущую ревизию `main`, содержащую `serving_profile=joint_v1`; прежний коммит `bdd6e51` воспроизводит другую модель. Одной замены CSV недостаточно.
